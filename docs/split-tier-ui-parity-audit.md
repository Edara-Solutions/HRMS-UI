# Split-tier portal parity review

Baseline: the last pre-split Admin and Company UI on `origin/dev` (`b8c3e9c`), compared with the split-tier `refactor/split-tier-users` UI (`fbddda1`) and the current backend route contracts. The old `/admin` audience is now `/platform`; this is a route and authorization migration, not a reason to discard useful presentation patterns. Screenshots supplied by the user show the same regressions in a running Platform session.

The old dashboards and Admin subscriptions table used checked-in sample data. Their figures, actions and statuses were not authoritative backend reads. The decision for this repair is to show dashboard samples in an explicitly labelled demo section and keep live workflow links and status panels separate. No old fixture value should be presented as a current tenant, payment or health fact.

## Reusable UI and structural findings

- Reuse the retained `DataTable`, `Card`, `Badge`, `Button`, `Dialog`, `ConfirmDialog`, `EmptyState`, `DateEdgeField`, audit filter components and page-owned query/command models. Table-to-card adaptation is already part of `DataTable`; the repaired registry tables use it.
- The older `PlanFormDialog` feature-chip pattern is useful, but its old hooks and unscoped Admin API are retired. The current plan editor should keep its generated schema and mutation preflight while using a dedicated, guided form. The old subscription table is inseparable from fixture data and should not be copied into live UI.
- The sidebar icon map omitted `plans`, `leads`, `conversion-requests`, `companies` and `subscriptions`; every missing key fell back to Home. Add explicit icons and a navigation regression test.
- The previous Admin and Company dashboards were intentionally deleted during the S12 reachability gate. Restoring labelled demo data requires new owned page slices, not reviving deleted `/admin` routes or unscoped clients.
- The current backend checkout has unrelated uncommitted seed work. This review reads its route source and the UI's vendored generated authorization/operation contracts; it does not modify backend files or claim that a running backend has been exercised.

## Required backend follow-up

1. Define a paginated Platform subscription overview response with Company identity, plan, status, trial/subscription dates and access flags if the old multi-company subscription table/filter/KPI workflow is intended to become live. Preserve per-Company reads for detail; do not fan out one request per row from the browser.
2. Define audience-specific dashboard aggregates only for metrics the product intends to make authoritative, with time window, currency and permission semantics. Until accepted, keep old metrics in a labelled demo section.
3. If Platform Company search must cover the whole registry rather than the current page, add server-side search parameters to the registry contract; the current local filter cannot find Companies on other pages.

This document is a source/code-contract comparison, not a production data audit. A final authenticated browser pass should compare English/Arabic, light/dark, narrow and desktop screens under read-only and full-access accounts.

## Verification status

The missing dashboard import and five icon fallbacks were reproduced before repair. The plan feature-array create bug was exposed by the create integration test and fixed in `catalogue-form.ts`. The email-deliveries table regression test failed on the absent `Email type` column before the table repair. Focused catalogue and deliveries tests then passed. `contract:check` detected the forbidden `src/pages/platform/dashboard` directory; moving the new page slice to `src/pages/platform/overview` resolved that retired-surface failure.

The affected-page Vitest run passed 95 tests across 12 files; the follow-up dashboard, registry and communications tests passed after the final UI changes. The production build and exact operation reachability gate passed. Biome checked the full UI tree; React Doctor's changed-file scan reported no remaining issues. Playwright passed 84 mocked-contract browser flows across English/Arabic, desktop/narrow and light/dark combinations with one Chromium worker. This verifies routing, responsive behavior, focus and core actions against declared fixtures, not a live deployed backend. A first six-worker run timed out during browser page setup on this host; the one-worker rerun passed. The repository's `bun run lint` passes Biome but Steiger currently crashes under installed Node 24 while loading its ESM config; this is a verification environment/tooling issue, not a clean lint verdict.
